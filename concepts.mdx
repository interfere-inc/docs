## Workspace

A workspace contains your team's surfaces, problems, integrations, and access settings. Its URL includes a slug, such as `acme` in `interfere.com/~/acme`. The CLI and API use that slug to select the workspace.

## Surface

A surface is an app you monitor, such as a web frontend or backend service. Give each app you deploy separately its own surface. A Next.js frontend and a NestJS API are two surfaces.

Each surface has a public ingestion key and secret credentials for permitted API operations. Connect it to its code repository and deployment platform from [Surfaces](https://interfere.com/~/*/surfaces).

## Evidence

Evidence supports an investigation. It can include an error, stack trace, release, log, or the session where an issue occurred. A finding records an occurrence that Interfere uses to investigate and group related symptoms.

## Problem

A problem groups occurrences of an issue, such as checkout failing when the cart is empty. Its investigation brings together supporting evidence, a likely cause, and relevant code. An investigation can be in progress or incomplete; review its status and evidence before acting on a conclusion.

### Statuses

| Status          | Meaning                                                                        |
| --------------- | ------------------------------------------------------------------------------ |
| Detected        | Interfere has detected an issue for investigation.                             |
| Reasoning       | The investigation is working through evidence and possible causes.             |
| Active          | The problem needs a fix.                                                       |
| In recovery     | Interfere is monitoring whether the problem has stopped.                       |
| Needs attention | The problem needs further review.                                              |
| Resolved        | The issue has stopped recurring. Interfere continues watching for regressions. |
| Dismissed       | Your team has decided not to act on the problem.                               |
| Failed          | The investigation could not complete. This does not mean the issue is fixed.   |

Interfere manages investigation, recovery, and resolution. Your team can dismiss a problem that does not need action. See the [problem view](/product/problems#work-the-problem) for assignment, priority, comments, and subscriptions.

### Fixes

An investigation can propose a code, configuration, or product change. Review the evidence and suggestion before applying a fix to your app.

## Regression

A regression is a resolved problem that appears again. Interfere compares new findings with earlier problems and can reopen a problem when the error returns. Release context helps identify which deployment brought it back.

## Release

A release identifies a version of your code. The Next.js and Vite build plugins derive release identity from your commit and publish build metadata. That connects telemetry to the code and deployment that produced it.

Build and runtime must use the same commit identity. In an environment without a git checkout, set `INTERFERE_SOURCE_ID` to the same commit SHA at build time and runtime. See the SDK's release configuration and the [CLI's build automation guidance](/integrations/cli#build-automation).

## Sources and destinations

A source is where your code lives, such as GitHub. A destination is where it runs, such as Vercel or Cloudflare. Connect them in [Settings → Integrations](https://interfere.com/~/*/settings/integrations) and map them to the relevant surfaces.

The [MCP server](/integrations/mcp), [CLI](/integrations/cli), and [Terraform provider](/integrations/terraform) let you work with Interfere from your own tools.
