Interfere uses public surface keys for telemetry and secret API keys for authenticated operations. Secret keys have explicit scopes and an expiration setting. Keep them in your secret manager or CI environment.

## Surface keys

Open a surface and select **Keys**. Use its public key in the SDK to capture telemetry. It is safe to include in browser code.

Use its secret key with `release:write` to register releases and upload source maps. Set `INTERFERE_API_KEY` in the build environment for SDK plugins. The CLI uses `INTERFERE_SECRET_KEY` for secret key authentication.

## Workspace keys

Use a workspace API key for unattended workspace operations, including Terraform. Its scopes determine which resources it can read or change.

For interactive work, sign in through [MCP](/integrations/mcp) or the [CLI](/integrations/cli). OAuth uses your existing workspace permissions.

## Create a workspace key

Send `POST /v3/workspaces/{workspaceSlug}/api-keys` as an authenticated workspace user. You need `org:workspace_auth:write` and every permission you grant to the key.

Authenticate with a user access token and send this request to create a Terraform credential. Set `INTERFERE_ACCESS_TOKEN` to that token and replace `acme` with your workspace slug:

```bash
curl --fail-with-body https://api.interfere.com/v3/workspaces/acme/api-keys \
  --header "Authorization: Bearer $INTERFERE_ACCESS_TOKEN" \
  --header "Content-Type: application/json" \
  --data '{
    "idempotencyKey": "9e3c0d0e-3bf7-48ae-9271-6ea58e7b970d",
    "name": "Terraform",
    "scopes": ["org:surfaces:read", "org:surfaces:write", "org:surfaces:delete"],
    "secondsUntilExpiration": 2592000
  }'
```

Generate a fresh UUID for each new key. If the response is uncertain, retry with the same UUID and request. The example expires after 30 days. Use a positive number of seconds for an expiring key or `null` for no expiry. Both `scopes` and `secondsUntilExpiration` are required.

Store the returned `apiKey.secret` in your secret manager. Save the key ID for revocation. For Terraform, provide the secret through `INTERFERE_TOKEN`.

You can also manage private keys with [Terraform](/integrations/terraform#manage-private-api-keys).

## Permission changes

A workspace key's access is limited to its explicit scopes and its creator's current workspace permissions. Removing the creator's membership removes the key's management access. A key does not grant permissions its creator lacks.

## Revoke a key

Send `DELETE /v3/workspaces/{workspaceSlug}/api-keys/{apiKeyId}` to revoke a workspace key. Update any automation using it with a replacement credential before revoking it if that automation must keep running.

For surface credentials, open the surface's key settings. Public ingestion credentials and secret build credentials serve different purposes; copy the credential required by your SDK or tool.
