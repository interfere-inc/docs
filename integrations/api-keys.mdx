SDK 13.0.x uses a workspace secret and a stable service name. Set `INTERFERE_API_KEY` in the build environment with `release:write`. The build plugin registers a release, bakes its release token into the browser bundle, and handles source maps automatically. Keep the workspace secret out of browser code.

For server telemetry, grant `org:telemetry:write` and provide the workspace secret to the server runtime. The [CLI](/integrations/cli) uses `INTERFERE_SECRET_KEY` for secret-key authentication; Terraform uses `INTERFERE_TOKEN`.

## Legacy keys

App public keys and App-bound build credentials are deprecated compatibility paths. New services use workspace secrets and build-generated release tokens. Retained public-key client options are documented for existing integrations, not required for keyless setup.

## Workspace keys

Use a workspace API key for unattended workspace operations, including Terraform. Its scopes determine which resources it can read or change.

For interactive work, sign in through [MCP](/integrations/mcp) or the [CLI](/integrations/cli). OAuth uses your existing workspace permissions.

For native OpenTelemetry ingestion, use a workspace key with **Send telemetry** (`org:telemetry:write`). See [OpenTelemetry ingestion](/sdk/otel-ingestion) for setup and exporter configuration.

## Create a workspace key

[Install the CLI](/integrations/cli#install-and-sign-in), then sign in through your browser:

```bash
interfere auth login --scheme oauth-production
```

Use an Owner or Admin account with permission to manage workspace authentication. You can only grant permissions your account already has.

Create a key for SDK builds and server telemetry. Replace `acme` with the workspace slug from your Interfere URL, and replace the example UUID with a new UUID:

```bash
interfere keys private create \
  --workspace acme \
  --name Storefront \
  --idempotency-key 9e3c0d0e-3bf7-48ae-9271-6ea58e7b970d \
  --scopes release:write \
  --scopes org:telemetry:write \
  --seconds-until-expiration 2592000 \
  --format json
```

The response contains `apiKey.id`, `apiKey.name`, and `apiKey.secret`. Save the ID for revocation and store the secret in your secret manager. Configure your CI environment to supply that secret as `INTERFERE_API_KEY` when it builds and runs the service.

This key expires after 30 days. Set the lifetime to the number of seconds your automation needs. Keep the same UUID and arguments if you retry an uncertain creation request; use a new UUID for a different key.

The example grants release publication and telemetry ingestion. For Terraform, create a separate workspace key with the permissions listed for the [resources](/integrations/terraform) you manage and supply it as `INTERFERE_TOKEN`. You can inspect all accepted fields with `interfere keys private create --schema`.

## Permission changes

A workspace key's access is limited to its explicit scopes and its creator's current workspace permissions. Removing the creator's membership removes the key's management access. A key does not grant permissions its creator lacks.

## Revoke a key

Create a replacement and update the automation that uses the old key. Then revoke the old key using its saved ID:

```bash
interfere keys private delete --workspace acme --api-key-id KEY_ID
```

Revocation prevents subsequent requests from using that credential.
