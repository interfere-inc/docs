Interfere uses public surface keys for telemetry and secret API keys for authenticated operations. Secret keys have explicit scopes and an expiration setting. Keep them in your secret manager or CI environment.

## Surface keys

Open a surface and select **Keys**. Use its public key in the SDK to capture telemetry. It is safe to include in browser code.

Use its secret key with `release:write` to register releases and upload source maps. Set `INTERFERE_API_KEY` in the build environment for SDK plugins. The CLI uses `INTERFERE_SECRET_KEY` for secret key authentication.

## Workspace keys

Use a workspace API key for unattended workspace operations, including Terraform. Its scopes determine which resources it can read or change.

For interactive work, sign in through [MCP](/integrations/mcp) or the [CLI](/integrations/cli). OAuth uses your existing workspace permissions.

## Create a workspace key

[Install the CLI](/integrations/cli#install-and-sign-in), then sign in through your browser:

```bash
interfere auth login --scheme oauth-production
```

Use an Owner or Admin account with permission to manage workspace authentication. You can only grant permissions your account already has.

Create a key for Terraform to manage surfaces. Replace `acme` with the workspace slug from your Interfere URL, and replace the example UUID with a new UUID:

```bash
interfere keys private create \
  --workspace acme \
  --name Terraform \
  --idempotency-key 9e3c0d0e-3bf7-48ae-9271-6ea58e7b970d \
  --scopes org:surfaces:read \
  --scopes org:surfaces:write \
  --scopes org:surfaces:delete \
  --seconds-until-expiration 2592000 \
  --format json
```

The response contains `apiKey.id`, `apiKey.name`, and `apiKey.secret`. Save the ID for revocation and store the secret in your secret manager. Configure your CI environment to supply that secret as `INTERFERE_TOKEN` when it runs Terraform.

This key expires after 30 days. Set the lifetime to the number of seconds your automation needs. Keep the same UUID and arguments if you retry an uncertain creation request; use a new UUID for a different key.

The example grants surface management only. To manage workspace settings or issue additional keys, add the permissions listed for those [Terraform resources](/integrations/terraform). You can inspect all accepted fields with `interfere keys private create --schema`.

## Permission changes

A workspace key's access is limited to its explicit scopes and its creator's current workspace permissions. Removing the creator's membership removes the key's management access. A key does not grant permissions its creator lacks.

## Revoke a key

Create a replacement and update the automation that uses the old key. Then revoke the old key using its saved ID:

```bash
interfere keys private delete --workspace acme --api-key-id KEY_ID
```

Revocation prevents subsequent requests from using that credential.

For surface credentials, open the surface's key settings. Public ingestion credentials and secret build credentials serve different purposes; copy the credential required by your SDK or tool.
