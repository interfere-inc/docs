The Interfere CLI v1.0.0 provides command-line access to workspace data and API operations. Commands and argument schemas come from the API contract.

## Install and sign in

```bash
npm install -g @interfere/cli
interfere auth login --scheme oauth-production
export INTERFERE_WORKSPACE=your-workspace
interfere problems list
```

Sign-in opens your browser for authentication and workspace selection. The CLI stores credentials in your operating system's credential store, and refreshes expired access tokens. Linux static builds use a credential file restricted to your user.

Native binaries support macOS on Apple Silicon and Intel, Linux on ARM64 and x64, and Windows on x64. Keep npm optional dependencies enabled so installation can select the binary for your platform.

## Discover commands and arguments

Use help to find commands and `--schema` to inspect a command's arguments before calling it:

```bash
interfere --help
interfere problems --help
interfere problems get --schema
interfere problems get --args.problem-id PROBLEM_ID
```

Workspace operations use `INTERFERE_WORKSPACE` or an explicit `--workspace` flag:

```bash
interfere problems list --workspace acme
```

## Inspect a problem

Read a problem, its timeline, and related findings in one command:

```bash
interfere problems inspect PROBLEM_ID --workspace acme
```

## Preview a request

```bash
interfere problems get --args.problem-id PROBLEM_ID --dry-run
```

`--dry-run` shows the request without sending it. It does not check your permissions or validate the request against live data. The API performs those checks when you execute the command.

## Use JSON in scripts

Piped output defaults to JSON. Set `--format json` to request JSON explicitly. Use `--query` for a JMESPath expression that selects fields from the output.

```bash
interfere problems list --format json
```

Errors in machine output modes are also JSON on stdout, with a nonzero exit status. Check the exit status before treating output as a successful response.

## Credentials

| Variable                 | Purpose                                                                                    |
| ------------------------ | ------------------------------------------------------------------------------------------ |
| `INTERFERE_WORKSPACE`    | Default workspace slug.                                                                    |
| `INTERFERE_ACCESS_TOKEN` | User access token for noninteractive requests.                                             |
| `INTERFERE_SECRET_KEY`   | Secret key for API operations that accept key authentication. Its scopes determine access. |
| `INTERFERE_PUBLIC_KEY`   | Public surface key for ingestion operations.                                               |
| `INTERFERE_ENVIRONMENT`  | API environment, `production` by default or `preview`.                                     |

Credentials are specific to the operations that accept them. A release-only key cannot manage workspace resources. See [API keys](/integrations/api-keys) for scope and expiry behavior.

The SDK build plugins read `INTERFERE_API_KEY`. The CLI reads `INTERFERE_SECRET_KEY`; use the variable expected by the tool you are running.

## Profiles

Use named profiles to keep workspace defaults and credentials together:

```bash
interfere profiles --help
```

Explicit flags override profile values. Profile values override environment variables. Keep separate profiles for separate API environments.

## Preview environment

```bash
export INTERFERE_ENVIRONMENT=preview
interfere auth login --scheme oauth-preview
interfere problems list --workspace your-preview-workspace
```

Preview uses a separate OAuth client, API endpoint, and stored credential. This setting selects the Interfere API environment; it does not filter your app's production or staging telemetry.

## Build automation

The [Next.js](/sdk/next-js) and [Vite](/sdk/vite) plugins register releases and upload source maps during builds, including builds deployed to AWS, Fly, Render, or your own servers. For other build systems, follow the [TypeScript SDK release workflow](/platform-sdk/typescript#register-releases-and-upload-source-maps). Inspect the CLI's generated command help and schema for the required request fields.

Do not automatically repeat a write after a timeout. Check whether the operation succeeded, and preserve its idempotency key when retrying an operation that supports one.
