The Interfere Terraform provider manages workspace settings and API keys. Services identify themselves through a stable service name in telemetry and SDK build configuration.

## Configure the provider

Add the provider to your Terraform configuration:

```hcl
terraform {
  required_providers {
    interfere = {
      source = "interfere-inc/interfere"
    }
  }
}

provider "interfere" {}
```

Create a [workspace key](/integrations/api-keys#create-a-workspace-key) for Terraform with the permissions required by the resources below. Supply the secret as `INTERFERE_TOKEN` through your shell or CI secret manager. A release-only key cannot manage workspace settings or credentials.

## Manage workspace settings

Use `interfere_workspace` to manage an existing workspace's name and slug:

```hcl
resource "interfere_workspace" "team" {
  workspace_slug = "acme"
  name           = "Acme engineering"
}
```

This resource adopts an existing workspace. It does not create one. Removing the resource from Terraform only removes it from state; it does not delete the workspace.

Grant the provider credential `org:workspace_basics:read` and `org:workspace_basics:write` for this resource.

```bash
terraform import interfere_workspace.team acme
```

## Legacy App resources

Provider 0.x App resources (named `interfere_surface*`) and `surface_slug` credential scoping are deprecated. Provider 1.0 removes them. Do not use them for new services. Review the [provider changelog](https://github.com/interfere-inc/terraform-provider-interfere/blob/main/CHANGELOG.md) and the schema for your pinned provider version before upgrading.

Retiring a resource from Terraform state is different from deleting retained data. When stopping management of a legacy resource, use a `removed` block with `lifecycle { destroy = false }` while still on the compatible provider version, and review the plan before upgrading.

## Manage private API keys

Use `interfere_private_key` to create a workspace secret for SDK builds and server telemetry:

```hcl
resource "interfere_private_key" "releases" {
  workspace_slug           = "acme"
  idempotency_key          = "c8a2c920-ff67-4ed0-a344-e3172279ae9d"
  name                     = "Storefront"
  scopes                   = ["release:write", "org:telemetry:write"]
  seconds_until_expiration = 2592000
}
```

The provider credential needs `org:workspace_auth:read` and `org:workspace_auth:write`. The credential must also be allowed to grant the requested scopes.

Supply the created secret to the SDK build and server as `INTERFERE_API_KEY`, then configure a stable `serviceName` in the [framework plugin](/sdk/configuration#service-names). The build bakes a release token for browser capture and handles source maps automatically.

The example expires after 30 days. Omit `seconds_until_expiration` or set it to `null` for no expiry. Changing grants or lifetime replaces the key, so choose a fresh creation UUID for the replacement.

The resource's `secret` output is sensitive and **is stored in Terraform state**. Use a state backend with access controls appropriate for credentials. Import restores metadata only; it cannot recover the secret.

```bash
terraform import interfere_private_key.releases acme/KEY_ID
```

## Recover from an uncertain request

The provider does not automatically retry API requests. After an uncertain create response, keep the original creation UUID and configuration when retrying.

An empty response or an HTTP error preserves state and reports an error, because missing permissions can also prevent a read. Check credentials and workspace access before changing state manually.
