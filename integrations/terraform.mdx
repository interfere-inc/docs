The Interfere Terraform provider manages existing workspace settings, surfaces, and private API keys.

## Configure the provider

Add the provider to your Terraform configuration:

```hcl
terraform {
  required_providers {
    interfere = {
      source = "interfere-inc/interfere"
    }
  }
}

provider "interfere" {}
```

Follow [Create a workspace key](/integrations/api-keys#create-a-workspace-key) to sign in with the CLI and create your first Terraform credential. Configure your shell or CI secret manager to supply the returned secret as `INTERFERE_TOKEN`. Surface management requires these scopes:

- `org:surfaces:read`
- `org:surfaces:write`
- `org:surfaces:delete`

Use a workspace API key for unattended runs. A release-only surface key cannot manage workspace resources.

## Manage workspace settings

Use `interfere_workspace` to manage an existing workspace's name and slug:

```hcl
resource "interfere_workspace" "team" {
  workspace_slug = "acme"
  name           = "Acme engineering"
}
```

This resource adopts an existing workspace. It does not create one. Removing the resource from Terraform only removes it from state; it does not delete the workspace.

Grant the provider credential `org:workspace_basics:read` and `org:workspace_basics:write` for this resource.

```bash
terraform import interfere_workspace.team acme
```

## Create a surface

```hcl
variable "workspace_slug" {
  type = string
}

variable "creation_id" {
  type = string
}

resource "interfere_surface" "app" {
  workspace_slug  = var.workspace_slug
  idempotency_key = var.creation_id
  name            = "Storefront"
  type            = "react"
}

output "surface_slug" {
  value = interfere_surface.app.slug
}
```

Supply values in `terraform.tfvars`:

```hcl terraform.tfvars
workspace_slug = "acme"
creation_id    = "9e3c0d0e-3bf7-48ae-9271-6ea58e7b970d"
```

Replace `acme` with your workspace slug and generate a nonzero UUID for this surface. Keep that UUID stable across plans and retries; do not use `uuid()` to generate a different value on every run.

```bash
terraform init
terraform plan
terraform apply
```

The resource returns `id` and `slug`. Surface creation also issues default credentials. Manage SDK and build credentials through the surface's key settings. They are not stored in Terraform state.

## Update or replace a surface

| Field             | Behavior                                                                           |
| ----------------- | ---------------------------------------------------------------------------------- |
| `name`            | Updates the existing surface. Use 1 to 48 characters.                              |
| `type`            | Requires replacement.                                                              |
| `workspace_slug`  | Requires replacement.                                                              |
| `idempotency_key` | Identifies the creation attempt. Use a new UUID for a replacement or new creation. |

Review a replacement plan before applying it. Deleting a resource from configuration causes Terraform to request deletion of the managed surface.

Supported framework values are `elysia`, `nest`, `nextjs`, `python`, and `react`.

## Import an existing surface

Add a matching resource block, then import with the workspace and surface slugs:

```bash
terraform import interfere_surface.app acme/storefront
```

The creation UUID cannot be recovered during import. Supply a new UUID in your configuration. The next apply records it without recreating the imported surface.

## Manage private API keys

Use `interfere_private_key` for a workspace automation key or a surface build key. Set `surface_slug` to scope a key to a surface; omit it for a workspace key.

```hcl
resource "interfere_private_key" "releases" {
  workspace_slug           = "acme"
  surface_slug             = interfere_surface.app.slug
  idempotency_key          = "c8a2c920-ff67-4ed0-a344-e3172279ae9d"
  name                     = "Release uploads"
  scopes                   = ["release:write"]
  seconds_until_expiration = 2592000
}
```

For workspace keys, the provider credential needs `org:workspace_auth:read` and `org:workspace_auth:write`. For surface keys, it needs `org:surfaces:read` and `org:surfaces:write`. The credential must also be allowed to grant the requested scopes.

The example expires after 30 days. Omit `seconds_until_expiration` or set it to `null` for no expiry. Changing grants or lifetime replaces the key, so choose a fresh creation UUID for the replacement.

The resource's `secret` output is sensitive and **is stored in Terraform state**. Use a state backend with access controls appropriate for credentials. Import restores metadata only; it cannot recover the secret.

```bash
terraform import interfere_private_key.releases acme/KEY_ID
```

## Recover from an uncertain request

The provider does not automatically retry API requests. After an uncertain create response, keep the original creation UUID and configuration when retrying.

If Interfere explicitly reports that a surface is deleted, the provider removes it from state. An empty response or an HTTP error preserves state and reports an error, because missing permissions can also prevent a read. Check credentials and workspace access before changing state manually.
