The [Inbox](https://interfere.com/~/*) groups related occurrences into problems. Use it to decide what needs attention and who should work on it.

## Find the problems to work on

Start with an environment filter, such as **production**, then narrow by surface, status, priority, or assignee. Use the problem ID filter to return to specific problems.

For example, filter to your checkout surface and production environment, then sort by affected users to review the problems with the widest impact first.

Open **Display** to switch between board and list views and sort by priority, affected users, first detected, or last detected. You can also show or hide failed investigations.

Press <kbd>Alt</kbd> <kbd>Shift</kbd> <kbd>F</kbd> to clear filters. On macOS, use <kbd>Option</kbd> for Alt.

## Assign and prioritize

Select a problem and press <kbd>A</kbd> to assign it or <kbd>P</kbd> to set its priority. Select several problems to apply the same change together.

| Shortcut           | Action                         |
| ------------------ | ------------------------------ |
| Arrow keys         | Move through problems          |
| Shift + arrow keys | Extend or reduce the selection |
| ⌘ A or Ctrl A      | Select all filtered problems   |
| Escape             | Clear the selection            |
| A                  | Assign the selection           |
| P                  | Set priority                   |
| S                  | Change your subscription       |

These shortcuts apply outside text fields.

## Open an investigation

Open a problem to read its explanation and inspect the [supporting evidence](/product/problems). A **Failed** investigation needs review; it does not mean the issue is fixed.

Subscribe with <kbd>S</kbd> to follow comments and status changes. Choose how you receive those updates in [Notifications](/product/notifications).

## Workspace activity

Open **Activity** for a chronological view of new problems, regressions, recoveries, surfaces coming online, and teammates joining. Select a problem event to open its investigation.

For example, after deploying a fix, check for a recovery event and open the problem to review subsequent occurrences. Use the Inbox when you need to filter or assign several problems.

Administrative changes, such as a role or credential change, appear in the [Audit log](/product/audit-log). Choose how updates reach you in [Notifications](/product/notifications).
