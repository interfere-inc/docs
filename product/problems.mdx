Open a problem from the [Inbox](/product/inbox) to see what happened, who it affected, and what Interfere found. A problem groups related occurrences so your team can work on one investigation.

## Check the impact

Review the affected users and occurrences before deciding priority. An error during checkout may need attention even if it affects fewer users than an error on a rarely used settings page.

Use the findings list to review occurrences by day. Expand a day to inspect individual records. Release and environment details help establish when the issue started and where it happens.

## Read the explanation and evidence

The timeline contains investigation updates and team discussion. Follow the evidence linked from an explanation to inspect the records behind it.

For a checkout error, that might mean opening the failing request's trace, finding the exception, and checking the referenced code in the release that produced it. Use **Jump to error** in the trace to locate the failing span, then inspect its stack frames and surrounding spans.

Browser and platform details can help narrow a problem to a specific environment. Open an affected [session replay](/product/session-replay) to see the actions leading up to the failure.

## Work the problem

Assign an owner with <kbd>A</kbd> and set priority with <kbd>P</kbd>. Edit the title or description to add context, and use timeline comments to discuss findings or mention teammates.

Subscribe with <kbd>S</kbd> to receive updates. If the explanation is wrong, use the feedback control and include the evidence that contradicts it.

Dismiss a problem when your team has decided it does not need action. Archive it to remove it from your working view. Neither action deploys a fix to your app.

## Statuses

| Status          | Meaning                                                     |
| --------------- | ----------------------------------------------------------- |
| Detected        | Interfere has detected an issue for investigation           |
| Reasoning       | The investigation is examining evidence and possible causes |
| Active          | The problem needs a fix                                     |
| In recovery     | Interfere is monitoring whether the issue has stopped       |
| Needs attention | The problem needs further review                            |
| Resolved        | The issue has stopped recurring                             |
| Dismissed       | Your team has decided not to act                            |
| Failed          | The investigation could not complete                        |

Interfere manages investigation, recovery, and resolution as it observes events. A resolved problem can reopen as a regression if the issue returns. [Release metadata](/sdk/releases) connects those occurrences to the code that produced them.

You can also inspect the investigation through [AI Agents](/integrations/plugins), [MCP](/integrations/mcp), or the [CLI](/integrations/cli#inspect-a-problem).
