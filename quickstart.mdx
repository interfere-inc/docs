Create a workspace, add Interfere to your app, and check that Interfere receives events.

## Create a workspace

Open [setup](https://interfere.com/onboarding). Choose a workspace name, URL slug, and company email domain.

The slug identifies your workspace in links and API requests. For `interfere.com/~/acme`, it is `acme`.

New workspaces use **Unrestricted** [data residency](/product/data-residency). Storage and processing are not restricted to a specific region. Use your team's email domain so colleagues can join through your [workspace domain settings](/product/settings#workspace-domains).

## Connect a service

Use [Interfere MCP](/integrations/mcp) to ask your coding agent to install the SDK, or follow the framework guide below. Give the service a stable name, such as `storefront`.

Create a [workspace secret](/integrations/api-keys) and set `INTERFERE_API_KEY` where the project builds. Framework builds need `release:write`; server telemetry also needs `org:telemetry:write` and the secret in the server environment. Keep the secret out of browser code.

For SDK 13.0.x production builds, the plugin registers a release and bakes its release token into the browser bundle. Source maps are handled automatically.

## Connect your code and deployment

Connect [GitHub](/integrations/github) and select the repository for your app. This gives investigations access to the code behind an error.

Deployment connections such as [Vercel](/integrations/vercel) and [Cloudflare Workers](/integrations/cloudflare-workers) enrich release information. Repository and deployment mappings are optional for SDK capture.

## Verify events

Build and deploy with the workspace secret available at build time and an environment label such as `staging`. Open your application and trigger an action, or run the test capture in your SDK guide.

Open [Services](/product/services), select the service name you configured, and check for incoming telemetry. Verify a production build artifact; keyless development-server capture is a separate capability.

Finish setup by choosing a plan in **Plans & Billing**. Only workspace billing admins can purchase a plan. Problems appear as Interfere detects and investigates issues.

## Open your first investigation

Open the [Inbox](/product/inbox), select the service and environment you just deployed, and open a detected problem. In **Timeline**, read the explanation. In **Findings**, open an occurrence and inspect its error and stack frames. For browser problems, open **Sessions** to replay the actions around the failure.

Follow [Investigations](/product/problems) for a worked example showing how to check the explanation against a trace, a release, and an affected session.
