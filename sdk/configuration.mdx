This page configures browser capture in Next.js, Vite + React, and TanStack Start. For Node.js and NestJS server processes, set the service name and environment through [OpenTelemetry resource attributes](/sdk/otel-ingestion#identify-services-and-deployments).

## Service names

Give each service a stable name, such as `storefront` or `checkout-worker`. Configure it at build time so release registration and runtime telemetry use the same identity:

<CodeGroup>

```ts Next.js
import { withInterfere } from "@interfere/next/config";

export default withInterfere({ serviceName: "storefront" }, {});
```

```ts Vite / TanStack Start
import { interfere } from "@interfere/vite/plugin";

interfere({ serviceName: "storefront" });
```

</CodeGroup>

Without an explicit name, the build plugin uses the unscoped `package.json` name. You can also set `OTEL_SERVICE_NAME` in the build and server environment.

The workspace secret selects the workspace. The build registers a release for the service and bakes its release token into the browser bundle. Browser capture, remote configuration, sessions, and replay use that token.

| Variable            | Where                    | What it does                                                                                                                            |
| ------------------- | ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| `INTERFERE_API_KEY` | Build and server runtime | Workspace secret. Builds need `release:write`; server telemetry needs `org:telemetry:write`. Never expose this through a public prefix. |
| `OTEL_SERVICE_NAME` | Build and server runtime | Stable service identity. Keep it consistent across deployments.                                                                         |

<Note>
  `INTERFERE_PUBLIC_KEY` and `VITE_INTERFERE_PUBLIC_KEY` are deprecated legacy inputs. They are not
  part of the SDK 13.0.x production setup.
</Note>

## Environments

On Vercel and Cloudflare, the SDK reads the environment from the platform. On other hosts it falls back to `NODE_ENV`. To label a self-hosted staging deployment, set `INTERFERE_ENVIRONMENT=staging` in its environment.

Interfere filters local-like environments such as `development`, `local`, and `test` before ingestion. Verify on a deployed environment such as a preview or staging deployment, or review your workspace’s environment filtering.

## Capture features

Configure features on the `InterfereProvider` you added during installation. Import it from `@interfere/next/provider` for Next.js or `@interfere/vite/provider` for Vite and TanStack Start. All features default to enabled, subject to [consent](/sdk/consent).

| Plugin       | Capture                                   |
| ------------ | ----------------------------------------- |
| `errors`     | Uncaught browser errors                   |
| `logs`       | Console output                            |
| `device`     | Browser and device information            |
| `pageEvents` | Page views and clicks                     |
| `rageClick`  | Repeated clicks that indicate frustration |
| `replay`     | Session recordings                        |

For example, disable replay and page events:

```tsx
<InterfereProvider plugins={{ replay: false, pageEvents: false }}>{children}</InterfereProvider>
```

Set `init({ tracing: false })` to omit browser tracing. Set `errorBoundary={false}` on the provider if you already report React render errors through another boundary.

## Custom ingest domain

Configure a subdomain for telemetry if requests to the default endpoint are blocked by browser extensions. Add the CNAME using the target shown in your dashboard, then set `apiHost`.

For Next.js:

```ts next.config.ts
import { withInterfere } from "@interfere/next/config";

export default withInterfere({
  interfere: { apiHost: "https://in.acme.com" },
});
```

For Vite, pass `apiHost` to the build plugin:

```ts
interfere({ apiHost: "https://in.acme.com" });
```

Interfere provisions TLS for the domain. Telemetry requests do not send cookies.
