---
title: "Next.js"
description: "Capture browser and server errors in a Next.js App Router app."
---

`@interfere/next` connects browser errors, session replay, and server requests to the same service. The build plugin uploads source maps so investigations can show your original code.

You need a Next.js 15.3 or later App Router app, React 19, and Node.js 24. Use the SDK 13.0.x production build flow below.

## Setup

<Steps>
  <Step title="Install the package">

<CodeGroup>

```bash npm
npm install @interfere/next
```

```bash pnpm
pnpm add @interfere/next
```

```bash Yarn
yarn add @interfere/next
```

```bash Bun
bun add @interfere/next
```

</CodeGroup>

  </Step>
  <Step title="Set your workspace secret">

Create a workspace secret in [Developer settings](https://interfere.com/~/*/settings/developer) with **Source maps** (`release:write`) for the build. For server telemetry, also grant **Send telemetry** (`org:telemetry:write`) and provide the secret to the server runtime.

```env
INTERFERE_API_KEY=YOUR_WORKSPACE_SECRET
```

Keep the secret out of browser code and public environment variables. During a production build, the plugin registers a release and bakes its release token into the browser bundle. Source maps are handled automatically. Choose a stable service name in the build configuration; it defaults to the unscoped `package.json` name. Use the same name for build and server telemetry.

  </Step>
  <Step title="Connect your build">

Wrap your existing Next.js config. The plugin registers releases and uploads source maps during production builds.

```ts next.config.ts
import { withInterfere } from "@interfere/next/config";
import type { NextConfig } from "next";

const config: NextConfig = {};

export default withInterfere({ serviceName: "storefront" }, config);
```

Keep `withInterfere()` outermost when composing config wrappers. See [Releases and source maps](/sdk/releases) if another tool also uploads source maps.

  </Step>
  <Step title="Start server and browser capture">

Create `instrumentation.ts` in the project root, or inside `src` if your app uses a `src` directory.

```ts instrumentation.ts
export { onRequestError, register } from "@interfere/next/instrumentation";
```

If you already initialize OpenTelemetry, follow [OpenTelemetry composition](/sdk/opentelemetry) instead of registering a second provider.

Create `instrumentation-client.ts` beside `instrumentation.ts`. Next.js loads it before the app becomes interactive.

```ts instrumentation-client.ts
import { init } from "@interfere/next/instrument-client";

init();
```

  </Step>
  <Step title="Wrap your root layout">

Wrap the root layout. The provider exposes identity and consent hooks and reports React render errors. Browser capture still requires the `init()` call above.

```tsx app/layout.tsx
import { InterfereProvider } from "@interfere/next/provider";
import type { ReactNode } from "react";

export default function RootLayout({ children }: { children: ReactNode }) {
  return (
    <html lang="en">
      <body>
        <InterfereProvider>{children}</InterfereProvider>
      </body>
    </html>
  );
}
```

Before recording customer sessions, set [consent at initialization](/sdk/consent) and review [replay masking](/sdk/replay-privacy).

  </Step>
</Steps>

## Verify capture

Verify the production build artifact. This setup does not promise token minting from the development server.

Build and deploy to staging, then report a test error from an existing button or event handler in your staging app:

```ts
import { capture } from "@interfere/next/instrument-client";

capture(new Error("Interfere setup test"));
```

Open [Services](/product/services) and select the service to confirm that traffic arrives, then remove the test call.

<Note>
  Legacy `INTERFERE_PUBLIC_KEY` configuration is deprecated. SDK 13.0.x production builds use the
  release token baked by the plugin.
</Note>
