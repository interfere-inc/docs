---
title: "OpenTelemetry composition"
description: "Compose Next.js instrumentation and avoid duplicate telemetry."
---

Use this guide when your Next.js app already initializes OpenTelemetry or receives telemetry through platform drains. To send data from a native OTel exporter or Collector, see [OpenTelemetry ingestion](/sdk/otel-ingestion).

## Use an existing OpenTelemetry provider

Use one OpenTelemetry bootstrap per process. Interfere's `register()` checks whether a tracer provider is already registered:

- With none, Interfere sets up tracing for you.
- With one, such as Sentry or `@vercel/otel`, Interfere uses it and leaves its exporters alone. Server errors still reach Interfere. Your traces reach Interfere only if that provider [exports them to Interfere](#send-your-providers-traces-to-interfere). Interfere logs one message saying so.
- If `dd-trace` traces the same process without its OpenTelemetry bridge, Datadog and Interfere record separate traces. Set `DD_TRACE_OTEL_ENABLED=true` and register Datadog's tracer provider before Interfere to keep one trace.

To keep your own provider on purpose, register it first, add Interfere's span processor to it, then call `register()` with `tracing: "application"`:

```ts instrumentation.ts
import { registerOTel } from "@vercel/otel";
import {
  correlationSpanProcessor,
  register as registerInterfere,
} from "@interfere/next/instrumentation";

export { onRequestError } from "@interfere/next/instrumentation";

export async function register() {
  registerOTel({
    serviceName: "@acme/storefront",
    spanProcessors: [correlationSpanProcessor(), "auto"],
  });

  await registerInterfere({ tracing: "application" });
}
```

`correlationSpanProcessor()` copies Interfere's correlation baggage onto your server spans, so they carry the browser session. Your provider needs a W3C baggage propagator for it; the `@vercel/otel` defaults include one. `tracing: "application"` confirms the setup and silences the message.

## Send your provider's traces to Interfere

On Vercel, enable a [Vercel trace drain](/integrations/vercel#trace-and-log-drains) for the app. Elsewhere, point your provider's OTLP exporter at Interfere with the same `INTERFERE_API_KEY` the SDK uses. The key needs the **Send telemetry** permission.

```bash
OTEL_EXPORTER_OTLP_ENDPOINT="https://api.interfere.com/drain"
OTEL_EXPORTER_OTLP_PROTOCOL="http/protobuf"
OTEL_EXPORTER_OTLP_HEADERS="Authorization=Bearer%20${INTERFERE_API_KEY}"
```

The key selects the workspace, and your provider's `service.name` identifies the service. See [OpenTelemetry ingestion](/sdk/otel-ingestion#endpoints-and-authentication) for the endpoints and response codes.

## Avoid duplicate telemetry

If you already have an `onRequestError` handler, call Interfere's handler inside it as well. Keep both behaviors instead of replacing one export with the other.

Only one browser SDK should inject W3C trace context for a given request URL. If another SDK also writes `traceparent`, scope its injection to other hosts or use its vendor-specific propagation where supported. Competing headers can break browser-to-server correlation.

If your logger already emits console records through OpenTelemetry, pass `consoleBridge: false` to `register()`. Avoid adding a second HTTP instrumentation for requests already traced by Next.js or your host setup.

`register()` does not publish releases or upload source maps. Keep the [build plugin](/sdk/releases) configured.

## Browser-to-server traces

Keep both the build plugin and browser initialization from the [Next.js guide](/sdk/next-js). On dynamically rendered pages, they connect browser activity to the server request. The composed setup above also needs `correlationSpanProcessor()` for that connection.

Static pages and Edge-rendered pages start separate browser traces. Capture still works, but those pages do not have the same server-to-browser link.

## Server telemetry

The Node.js and Edge server runtimes send with `INTERFERE_API_KEY` when it is set where the server runs. Give the key the **Send telemetry** permission. Without it, the server sends with the public key.

Under `@vercel/otel`, a direct OTLP exporter flushes inside `waitUntil`, so each invocation stays billed until the export finishes. With a [Vercel trace drain](/integrations/vercel#trace-and-log-drains) enabled for the app, the SDK switches to drain mode automatically and avoids that cost: Vercel ships spans out of process. Without a drain, the SDK exports directly and caps each export on Vercel at 2 seconds.
